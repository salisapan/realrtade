# Ecosystem coverage: Google, Microsoft, Meta

Glance closes open loops. Gmail is where it starts today.

This page answers one question for the early-adopter release (owner, 2026-10-20): for every tool in the three ecosystems, what can Glance do today, is it read back and undoable, has anyone run it live, and what is missing. It is status, not the product definition. The locks are in `docs/vault/product-locks.md`: every integrated product is on by default with one consent per ecosystem, the Do It card pops up on its own, native embeds on every device are part of done, a close needs ProofOfClose and Undo, nothing sends on its own, and anything Glance made stays editable.

Source for each line: the code named, `docs/open-tasks.md` rows, and `docs/vault/decisions.md`. Nothing here was run live by the author of this page. "Live Gate" means a person ran it in the real app and the result is recorded; "not run" means no record.

Reading the columns: **Built** is code with corpus tests. **Proof** is a read-back by id (`fetchedBack: true`) plus Undo. **Live Gate** is the recorded real-app check. **Gap** is what stops it being done.

## What this means for the friends release

- **Closest to done:** Outlook mail, To Do and OneDrive (live Gates passed on earlier packages), then Gmail with Tasks, Calendar and Drive (built and heavily tested, no recorded PASS on 0.9.56).
- **Built but never seen live:** Docs, Sheets, Word, Excel, Teams drafts, Contacts, and every Meta surface.
- **Not started:** Forms, Keep, SharePoint, OneNote, PowerPoint, Facebook Pages, Threads, WhatsApp Business.
- **The learning loop:** the on-device threshold and Execution Memory learn from each person's clicks. The export of own-use decisions for training the model (`docs/glance-ai/learning-from-use.md`, paths A to D) is not built in the extension, so "the system learns from everyone's use" is true per person and not yet across people.
- **The release gate:** a package must pass the regression corpora first. On 2026-10-20 five corpora are red on the working branch tip: `card-decision` (Outlook Why-not-shown reason, PR #143), `flip-sample-0956`, and three that pass only with the clock set back to 2026-10-16 (`realshape-0956`, `negation-conditional`, `regress-144`), so they are date-bound fixtures. Four more were stale fixtures and are fixed. A fresh environment also needs `npm i` in `flow-trial-extension/` for jsdom.

## Run discipline (read before every ecosystems run; owner asked to cut waste, 2026-10-21)

- **Never idle (owner, 2026-10-23: «אתה עובד אצלי ואתה צריך ליצור יכולות חדשות»).** Every run ships one new user-facing capability. When a row looks blocked, pick the next buildable idea on the same surfaces (a new intent kind, a new close for a chat or mail the judge already sees, a missing Hebrew form, an Outlook browser spec for a built close) and write the blocker to `docs/open-tasks.md`. A run with no new capability is a failed run; do not report it as idle. **Grok sync:** at the start of every run, `git fetch` and read `git log` and `docs/glance-ai/card-requests-*.md` for what the Grok bot pushed (designs, answers to requests); build against it, and write any card the existing canonical one cannot show as a new request line there, so the Grok bot picks it up from git.
- **A and B do not share files in the same hour.** A: Google, the phone card, system notices; B: chat cards, Outlook, mail-sentence breadth. If your side is empty, you are idle; do not take the other side's row.
- **Tests:** run the corpora for what you touched plus `docs-consistency` and `identity-copy` on every run; run the whole corpus sweep and the full headless e2e once, on the last run you make in a day, not on every run.
