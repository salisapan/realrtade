# Engineering audit

Repo-only review, 2026-09-27. Nothing here was checked against live Netlify,
Supabase, or the Chrome Web Store. If a table or secret exists only in a
dashboard, this document cannot see it.

Flow and Glance stay two products. Glance (Free, and the unbuilt Pro tier)
is the self-serve extension. Flow is the regulated-org offering sold as a
scoped project. See `docs/product-architecture.md`.

## Architecture map

One git repo, four runtimes that do not import each other, plus a video
package. The Gmail add-on bundles a copy of the extension's judgment; it
does not import it at runtime.

**Glance (Flow Trial) is the only product with an application.**
`flow-trial-extension/` is a Manifest V3 Chrome extension. Entry points:
`manifest.json` (content script limited to `https://mail.google.com/*`),
`src/content-gmail.js` (chip and sidebar), `src/judgment.js` plus
`src/extract.js` (on-device scoring), `src/background.js` (credentials and
the five write paths). Setup UI is `popup/popup.html`. OAuth token exchange
does not live in the extension; it calls
`https://theflow-ai.com/.netlify/functions/*-oauth-exchange` under
`flow-landing/netlify/functions/`. The public inbox demo
(`flow-landing/missed-deadline.html`) loads a hand-copied engine,
`flow-landing/assets/glance-engine.js`, regenerated by
`scripts/build-glance-engine.sh`.

**Update:** `glance-gmail-addon/` is a Gmail Workspace add-on for web and the
Gmail iOS/Android apps. It bundles this same judgment and runs it in Google
Apps Script, not on the device. It is not a Workspace Marketplace listing.

**Flow (enterprise) in this repo is the marketing site and its lead path.**
`flow-landing/` is static HTML. `netlify.toml` sets an empty build command,
publishes `.`, and points functions at `netlify/functions`. Homepage
qualification goes through `submit-waitlist.js`; enterprise enquiries from
`contact.html` go through `submit-lead.js`; double opt-in mail is
`send-confirmation.js` and `confirm-signup.js`. Copy on `pricing.html`,
`security.html`, and `index.html` names an admin console, SSO, an audit
log, and Flow-Edge. This tree has no code for those. That matches the
written sales motion (quote, then a project). It is not evidence about
systems that might exist outside this repository.

**Glance Pro is not a third codebase.** `pricing.html` collects an email
(`source: 'pricing-pro'`) and `send-confirmation.js` accepts `kind: 'pro'`.
There is no checkout. `docs/product-architecture.md` §2.4 already says the
Pro feature list is unsigned.

**The repo root is a different product.** `index.html` is titled
`crowdfunding-clarity`. `src/pages/Landing.tsx` is a RealTrade investor
site (Vite, React, shadcn). Its Supabase client
(`src/integrations/supabase/client.ts`) points at project
`nlvljclvoguvrnntwufu`, and `src/integrations/supabase/types.ts` describes
`developers`, `investments`, `profiles`, and `properties`. A search of
`src/` finds no Glance or theflow-ai references. `README.md` is still the
Lovable template. `action-graph-video/` is a separate Remotion package
(`action-graph-video/package.json`) and is not referenced by the site or
the extension deploy.

## Top 3 build priorities

### 1. Make a confirmed Glance signup installable from this tree

`flow-landing/netlify/functions/download-trial-zip/download-trial-zip.js`
reads `flow-trial-extension.zip` beside itself. No `.zip` is in the
repository, so a deploy of this function directory has nothing to attach.
Four connectors are still placeholders: `flow-trial-extension/src/background.js`
sets `HUBSPOT_CLIENT_ID`, `SALESFORCE_CLIENT_ID`, `SLACK_CLIENT_ID`, and
`MONDAY_CLIENT_ID` to `YOUR_*` strings, and
`flow-trial-extension/src/connectors.js` marks those four `status: 'building'`.
Only Notion is `status: 'live'`.
`flow-trial-extension/docs/chrome-web-store-submission.md` still has open
items (listing screenshots, the dashboard form, those client IDs).

This is the product a visitor can actually run. The download and the four
OAuth destinations are the gap between “confirmed” and “installed.”

### 2. Check in the schema the landing functions write, on the project they call

Every Flow/Glance function hardcodes
`https://zjquktirlrhbqcnkfaok.supabase.co` (for example
`submit-waitlist.js`, `submit-lead.js`, `pricing.html`).
`supabase/config.toml` names a different project,
`nlvljclvoguvrnntwufu`, the same ref as the RealTrade client.

The only waitlist migration,
`supabase/migrations/20260705000000_create_waitlist.sql`, has
`email`, `lang`, `source`, `created_at`. `submit-waitlist.js` then
`PATCH`es `company`, `role`, and `website`. `submit-lead.js` inserts into
`public.leads`. No migration in `supabase/migrations/` creates `leads` or
those three columns. `src/integrations/supabase/types.ts` does not mention
`waitlist`, `leads`, or `catches` either. Whether the live
`zjquktirlrhbqcnkfaok` project was altered by hand is not visible here.

`supabase/functions/send-waitlist-welcome/index.ts` is a second mail path:
`FROM_ADDRESS` is still `Flow <hello@yourdomain.com>`. The body says the
Chrome extension judges on the device and the Gmail add-on runs the same
rules in Google Apps Script, not on the device. The pages call the Netlify
functions, not this edge function.

Homepage qualification fails closed when the remote table does not match
(`502`). The enterprise contact form (`submit-lead.js`) returns an error only
when the database write and the owner notification email both fail; if only
the write fails, the email says the lead was not stored and lists every field
to record by hand. The repo cannot recreate that database.

### 3. Resync the public demo engine with the extension

`flow-landing/missed-deadline.html` says the scan runs the unmodified
extension engine and that “what this page prints is what the product would
do.” `flow-landing/assets/glance-engine.js` is header-stamped
`Last synced: 2026-09-14`. Concatenating
`flow-trial-extension/src/{domains,extract,judgment}.js` does not match
that file. The extension source has Hebrew entity words, shekel-after-the-number
money parsing, Hebrew weekday dates, and Hebrew commitment/loss patterns.
The mirror does not. Nothing in root `package.json` runs
`scripts/build-glance-engine.sh`, and the repo has no CI workflow.

That demo is the public proof of the scorer. It is currently a different
program than the extension, including on Hebrew mail — the language the
landing site already ships.

Do not start SSO, an audit log, or Flow-Edge in this repository as the
next slice. Those names appear in marketing HTML only. Glance Pro’s
“more than one connector” and weekly digest are on `pricing.html`, but
`popup/popup.js` stores a single `connectorId`, there is no Stripe
integration, and §2.4 of the product spec says that list is not signed
off. Multi-connector is the first Pro change to design after that
sign-off, not a compliance feature.

## Blockers visible in the repo

- **No env template.** `.gitignore` allows `!.env.example`, and no
  `.env.example` exists. Functions read, and refuse to run without:
  `SUPABASE_SERVICE_ROLE_KEY`, `EMAIL_VERIFY_SECRET`, `RESEND_API_KEY`,
  `ANTHROPIC_API_KEY` (`glance-assist.js`), and per-connector
  `*_CLIENT_ID` / `*_CLIENT_SECRET` pairs. `GA4_MP_API_SECRET` and
  `EXTRA_EXTENSION_IDS` are also read. Values are not in git; whether
  Netlify has them set was not checked.
- **Diagnostic gap.** `check-email-config.js` reports Resend and the
  HubSpot pair only. It does not mention Supabase, Salesforce, Slack,
  Monday, or Anthropic.
- **Model not chosen.** `glance-assist.js` calls `claude-opus-5` under a
  `TODO(owner)` to pick the production model. Without
  `ANTHROPIC_API_KEY` the handler returns not-configured.
- **No CI.** No `.github/` workflows. Root `package.json` depends on
  `@playwright/test` and has no `test` script and no Playwright config.
  The only behavioral test found is
  `flow-trial-extension/test/judgment-corpus.cjs` (`node test/judgment-corpus.cjs`).
- **Pipedrive** is `status: 'planned'` in `connectors.js` and has no write
  path. Not a blocker for the five destinations already named.
