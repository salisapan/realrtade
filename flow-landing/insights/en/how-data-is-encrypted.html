How your data is encrypted

"Encrypted" appears on every security page. What matters is where data is encrypted, with which keys, who holds them, and what is left unencrypted while it is being processed.

Aug 31, 2026·3 min read

In short

  • In transit: TLS 1.3 is the current standard for data moving over a network.
  • At rest: AES is the standard cipher; key management is where designs differ.
  • In use: data is usually decrypted while processed, so where processing runs matters.

In transit

Data moving between your office and a service should travel over TLS. Version 1.3, defined by the IETF in RFC 8446, removed older and weaker options. Ask which versions a vendor accepts, not only whether it uses TLS.

At rest

Stored data is usually encrypted with AES, the standard published by NIST as FIPS 197. The cipher is rarely the weak point. The keys are.

Keys decide everything

NIST SP 800-57 sets out how keys should be generated, stored, rotated and destroyed. Questions worth asking:

  • Who can use the keys that protect your data, and is that access logged?
  • Are keys separated per customer, or shared?
  • Can a key be revoked, and what happens to the data when it is?

Many systems use envelope encryption: data keys encrypt the data, and a master key, kept in a dedicated key service, encrypts the data keys.

In use

To process data, a system normally has to decrypt it in memory. Encryption at rest and in transit does not cover that moment. Two things reduce the exposure: sending less sensitive data in the first place, and processing it on hardware you control.

In Flow

In Flow's cloud, sensitive data is masked before any processing. With Flow-Edge or Flow-Onprem, processing happens on the employee's computer or on a server in the office, so the content is decrypted only there. Ask us, as you would ask any vendor, for the details in writing.
