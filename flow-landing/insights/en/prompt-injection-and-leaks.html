Prompt injection and leaks

An AI system that reads email and documents reads whatever an outsider decides to put in them. Some of that text may be written to steer the system. That is prompt injection.

Aug 31, 2026·3 min read

In short

  • Any content the system reads can carry instructions: email, PDFs, web pages.
  • Limit what the system can do, not only what it is told.
  • Human approval before sensitive actions is one of the strongest controls.

How the attack works

In direct injection, a user types instructions meant to override the system's rules. In indirect injection, the instructions hide in content the system processes: a line in an email, white text in a PDF, a comment on a web page. OWASP ranks prompt injection as the first risk in its list for applications built on language models. MITRE ATLAS catalogues it among real techniques used against AI systems.

What an attacker wants

  • To make the system send data somewhere it should not go.
  • To make it take an action: a payment, a message, a change to a record.
  • To make it ignore a rule, such as a check or an approval.

Controls that help

OWASP's guidance includes several that apply to any office:

  • Least privilege: the system gets only the access each process needs.
  • Keep sensitive functions in code, not in the model's free choice.
  • Treat external content as data to read, never as instructions to follow.
  • Require human approval for high-risk actions.

How Flow approaches it

In Flow, the office decides which systems are connected and with which permissions, and Flow gets the access each process needs. An approved action runs as a defined process, not as free model output, and nothing that matters runs before a person approves it with Do It. The office can revoke Flow's access to a connected system at any time, directly in that system's permission settings.
