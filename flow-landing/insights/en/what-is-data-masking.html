What is data masking?

Masking replaces sensitive details with stand-ins before data is processed. It sounds simple. In practice there are several techniques, and each protects something different.

Aug 31, 2026·3 min read

In short

  • Masking hides values; tokenization replaces them with reversible tokens.
  • Pseudonymised data can still be linked back to a person with the key.
  • The hard part is finding the sensitive details in free text in the first place.

The main techniques

  • Static masking: a copy of the data with sensitive values replaced, used for testing or analysis.
  • Dynamic masking: values are hidden or replaced as data is read, depending on who is asking.
  • Tokenization: each value is replaced with a token, and a separate, protected table maps tokens back to the originals.
  • De-identification: removing or changing details so that records cannot reasonably be linked to a person. NIST SP 800-188 describes the techniques and the governance around them.

Pseudonymised is not anonymous

GDPR Article 4 defines pseudonymisation as processing data so it can no longer be attributed to a person without additional information, kept separately and protected. The key still exists. That is why pseudonymised data is still treated as personal data, and why the key must be protected as carefully as the data.

Finding what to mask

Masking structured fields is easy. Emails, contracts and chat messages are not structured. A system has to recognise names, ID numbers, account numbers and addresses inside sentences, in more than one language, before anything else can happen. NIST SP 800-122 is a useful guide to what counts as personally identifiable information.

How Flow uses it

In Flow's cloud, sensitive data is masked before any processing: a name becomes a placeholder such as [CLIENT_1], and the real identifier never reaches a prompt, a log or a provider. Masking reduces risk; it does not replace architecture. When data must stay in the building, use Flow-Edge or Flow-Onprem.
