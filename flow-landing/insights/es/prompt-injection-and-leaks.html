Inyección de prompts y fugas

Un sistema de IA que lee correos y documentos lee todo lo que un tercero decida poner en ellos. Parte de ese texto puede estar escrito para dirigir el sistema. Eso es la inyección de prompts.

31 de agosto de 2026·3 min de lectura

En resumen

  • Cualquier contenido que lea el sistema puede llevar instrucciones: correos, PDF, páginas web.
  • Limite lo que el sistema puede hacer, no solo lo que se le dice.
  • La aprobación humana antes de las acciones sensibles es uno de los controles más sólidos.

Cómo funciona el ataque

En la inyección directa, un usuario escribe instrucciones pensadas para saltarse las reglas del sistema. En la inyección indirecta, las instrucciones se esconden en contenido que el sistema procesa: una línea en un correo, texto en blanco en un PDF, un comentario en una página web. OWASP sitúa la inyección de prompts en primer lugar de su lista de riesgos para aplicaciones basadas en modelos de lenguaje. MITRE ATLAS la recoge entre las técnicas que se usan realmente contra sistemas de IA.

Lo que busca el atacante

  • Que se envíen datos adonde no deben ir.
  • Provocar una acción: un pago, un mensaje, un cambio en un registro.
  • Que se ignore una regla, como una comprobación o una aprobación.

Los controles que ayudan

Las recomendaciones de OWASP incluyen varios, válidos para cualquier organización:

  • Mínimo privilegio: el sistema recibe solo el acceso que necesita cada proceso.
  • Mantener las funciones sensibles en el código, no a libre elección del modelo.
  • Tratar el contenido externo como datos que se leen, nunca como instrucciones que se siguen.
  • Exigir aprobación humana para las acciones de riesgo.

El enfoque de Flow

En Flow, es la organización la que decide qué sistemas se conectan y con qué permisos, y Flow recibe el acceso que necesita cada proceso. Una acción aprobada se ejecuta como un proceso definido, no como una salida libre del modelo, y nada importante se ejecuta antes de que una persona apruebe con Do It. La organización puede revocar en cualquier momento el acceso de Flow a un sistema conectado, directamente en la configuración de permisos de ese sistema.
